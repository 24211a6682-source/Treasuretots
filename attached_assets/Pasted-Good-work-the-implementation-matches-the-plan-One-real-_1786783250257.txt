FIX REQUIRED — webhook idempotency gap (failed → paid transition)

In artifacts/api-server/src/routes/webhooks.ts, the payment.captured /
order.paid handler currently updates the order with:

  WHERE paymentStatus = "pending"

This correctly blocks re-processing an already-"paid" order. But it also
silently blocks the legitimate case where a customer's first payment attempt
failed (order marked "failed" by an earlier payment.failed webhook), then
they retried and succeeded. Razorpay allows multiple payment attempts against
the same order_id — a payment.captured webhook can legitimately arrive for an
order currently marked "failed". Right now that UPDATE matches zero rows, so
the order is stuck "failed" forever even though Razorpay actually captured
the money and stock is never decremented for a paid order.

Fix: widen the WHERE clause to accept either "pending" or "failed":

  .where(and(
    eq(ordersTable.razorpayOrderId, razorpayOrderId),
    inArray(ordersTable.paymentStatus, ["pending", "failed"])
  ))

Keep the existing behavior of skipping the update (and the stock decrement)
whenever the order is already "paid" — that part is correct and must not
change. Apply the same reasoning to the payment.failed handler: it should
only be allowed to move "pending" -> "failed", never touch an order that's
already "paid" (your current logic already does this correctly — just
confirm it after the change above).
